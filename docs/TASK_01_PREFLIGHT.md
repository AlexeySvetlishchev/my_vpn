# TASK 01 — только проверка способа доступа

**Режим:** READ_ONLY, без подключений к production, до согласования механизма доступа.

**Задача:** определить, может ли текущая среда Work безопасно подключаться по SSH к публичной Ubuntu VPS и каким именно инструментом. Использовать короткий ответ; не проводить самостоятельное исследование архитектуры.

**Вход:** документация проекта (`README.md`, `docs/*.md`). IP-адресов, логинов и ключей пока нет.

**Разрешено:** проверить наличие конкретного терминала/инструмента для SSH, сформулировать механизм аутентификации без публикации ключей, описать ограничения среды.

**Запрещено:** веб-ресерч, проектирование VPN, установка/настройка, аудит серверов без доступов, запрос приватных ключей в чат, любые сетевые подключения к неизвестным VPS.

**Формат ответа — максимум 10 строк:**

1. SSH из этой среды: `ДА/НЕТ/НЕИЗВЕСТНО`.
2. Конкретный инструмент и его ограничения.
3. Как безопасно организовать временный доступ **без отправки ключа в чат**.
4. Если SSH недоступен, предложить read-only скрипт, запускаемый владельцем (сам скрипт пока не писать).
5. Что необходимо от владельца для следующего этапа.

**Готово, когда:** понятен исполнимый путь получения данных для аудита. Не следует делать никаких последующих действий без новой конкретной задачи.
