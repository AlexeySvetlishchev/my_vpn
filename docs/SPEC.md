# SPEC — VPN RU → FR (сменяемый зарубежный egress)

Редакция: 2026-11-07 · актуализация baseline v1.1 по решениям владельца и read-only аудиту.

> **Статус:** утверждённый проектный baseline; полный клиентский сервис ещё не развёрнут. TASK 06 host-level RU↔FR transport включён и проверен отдельно, без клиентского egress.

## 1. Цель и масштаб

**УТВЕРЖДЕНО.** Построить легковесную инфраструктуру для порядка 10–50 VPN-клиентов с единой точкой подключения в РФ, автоматическим выбором страны выхода и независимым управлением. Приоритеты: практическое удобство человека, сохранение безопасности и существующего сервиса, минимальное потребление ресурсов.

Фактические VPS (наблюдения read-only аудита 2026-11-07): **RU** `218852`/`218852.ru`, `137.22.146.212`, Ubuntu 24.04, 2 vCPU/3915 МиБ; **FR** `hiplet-142983`, `45.15.128.138`, Ubuntu 24.04.5, **1 vCPU/961 МиБ**. На RU установлены средства AmneziaWG; активного клиентского VPN нет. На FR работает необходимый владельцу **production AmneziaVPN** в Docker (`amnezia-awg2`, UDP `40905`); сохранять его без нарушения работы, **нет задачи его удалять**. Пригодность FR для 10–50 клиентов не доказана и требует тестов производительности. NL — бывший целевой узел, сейчас вне scope.

## 2. Передача трафика

- **УТВЕРЖДЕНО.** Клиенты подключаются к VPS РФ по **AmneziaWG**; приложение на устройстве может быть совместимым клиентом AmneziaVPN/AmneziaWG.
- **УТВЕРЖДЕНО.** Российские IP-назначения выходят напрямую с IP VPS РФ; остальные публичные IPv4 — через отдельный межсерверный туннель к сменяемому зарубежному выходу (первый кандидат — FR) и выходят с его публичного IPv4.
- **УТВЕРЖДЕНО.** Поддерживаются администраторские исключения для принудительного направления выбранных IP/CIDR через зарубежный egress.
- **УТВЕРЖДЕНО.** При отказе зарубежного выхода трафик, отнесённый к зарубежному egress, блокируется; **аварийного выхода через РФ нет**. Российский прямой выход должен сохраняться, если RU доступен.
- **УТВЕРЖДЕНО.** Обычный WireGuard RU↔FR не используется: владелец сообщил о нестабильном испытании. Для отдельного межсерверного транспорта используется userspace AmneziaWG (`amneziawg-go`) с интерфейсом `awg-transport`, `10.203.254.0/30`, UDP `51983`, MTU `1280`, systemd автозапуском и лёгким TCP/UDP health-check. TASK 06 проверил handshake, двусторонний echo и восстановление после перезапуска каждой собственной службы. Это не включает клиентские маршруты/egress; клиентский IPv6 отсутствует в первой версии, IPv6 хоста отключать нельзя.
- **УТВЕРЖДЕНО.** Один лёгкий DNS-резолвер/форвардер для клиентов на VPS РФ; географически раздельный DNS не входит в первый этап.
- **УТВЕРЖДЕНО.** Списки российских сетей и исключений обновляются автоматически ориентировочно каждые 12 часов; ошибка обновления не должна уничтожать предыдущую рабочую конфигурацию.

## 2.1. Сменяемый зарубежный выход

- **УТВЕРЖДЕНО:** смена IPv4 и полная замена зарубежной VPS осуществляются без изменения клиентских конфигураций RU AmneziaWG. Начальный кандидат — `hiplet-142983`; роль production egress утверждается только после испытаний.
- **УТВЕРЖДЕНО:** смена endpoint — управляемая операция `vpnctl`, с блокировкой конкурирующих изменений, аудитом, проверкой активного пира, реального внешнего IP и fail-closed. Имя CLI-команды и hostname пока **ОТКРЫТО**; пример старого `nl-egress.internal` не является утверждённой настройкой.
- **ПРОВЕРИТЬ:** способ стабильного именования/разрешения endpoint (`/etc/hosts` — один из вариантов), применение к конкретной реализации транспорта, идентичность удалённого пира, safe rollback, маршруты и NAT новой VPS. Изменение одного hostname не считается переключением действующего соединения.
- **УТВЕРЖДЕНО:** текущий FR AmneziaVPN не является межсерверным транспортом по умолчанию; новый тракт проектировать изолированно. Никакого автоматического удаления Docker или старого VPN после запуска новой системы.

## 3. Пользователи и профили

- **УТВЕРЖДЕНО.** Пользователя создаёт администратор вручную либо через одобрение заявки, принятой через разрешённый интерфейс.
- **УТВЕРЖДЕНО.** Имя вводит человек. Если создан `Ivan`, то в CLI, боте, статистике и списках пользователь отображается **Ivan**, а не `user_001` или UUID.
- **УТВЕРЖДЕНО.** Имена пользователей уникальны без учёта регистра. При конфликте понятная ошибка и повторный выбор имени. Отображаемый регистр исходного имени сохраняется.
- **УТВЕРЖДЕНО.** Один пользователь может иметь несколько независимых VPN-аккаунтов/профилей — по одному на устройство. Каждый имеет собственные ключи, назначенный VPN IP, статус, лимиты скорости и статистику.
- **УТВЕРЖДЕНО.** Стандарт имени профиля и выдаваемого файла: `ИмяПользователя_ИмяУстройства` (подчёркивание, **не дефис**), например `Ivan_iPhone.conf`, `Ivan_MacBook.conf`. Имена устройств уникальны в пределах пользователя.
- **УТВЕРЖДЕНО.** Телефон, email, Telegram ID и прочие внешние идентификаторы **не являются обязательными полями пользователя или VPN-аккаунта**. Пользователь VPN может вообще не иметь Telegram.
- **УТВЕРЖДЕНО.** Администратор способен создавать и обслуживать пользователя без Telegram у получателя, получая конфигурацию для внешней передачи.
- **УТВЕРЖДЕНО.** Обычный пользователь не может менять лимиты скорости; лимиты назначает и меняет только администратор.
- **ПРОВЕРИТЬ.** Точное отображение названия после импорта в каждое целевое приложение; не обещать, что все версии клиента автоматически применят имя файла.
- **ОТКРЫТО.** Допустимый набор символов пользовательского имени и имени устройства, политика переименования, число устройств на одного пользователя и значения лимитов по умолчанию. Составные имена не должны ошибочно разбираться по символу `_`; в модели пользователя и устройства имена хранятся раздельно.

## 4. Управление — без зависимости от Telegram

- **УТВЕРЖДЕНО.** Ядро: локальный VPN Manager; самостоятельный CLI является обязательным рабочим интерфейсом. Telegram — **опциональный адаптер** к тому же менеджеру, не источник истины.
- **УТВЕРЖДЕНО.** Прекращение работы Telegram/бота не прерывает существующие VPN-сессии, NAT, PBR, лимиты и сбор базовых метрик.
- **УТВЕРЖДЕНО.** CLI должен поддерживать создание, просмотр, блокировку пользователей/профилей, выдачу конфигураций, изменение скорости, получение состояния и статистики.
- **УТВЕРЖДЕНО.** Для Telegram-приёма заявок: строго одноразовое приглашение → заявка → одобрение уполномоченным администратором. Неавторизованные лица не получают административных возможностей или сведений об инфраструктуре.
- **УТВЕРЖДЕНО.** В Telegram администратор также может вручную создать пользователя и несколько профилей для человека без Telegram. Административные действия имеют ролевую модель Owner/Admin/User.
- **ОТКРЫТО.** Как пользователь без Telegram безопасно получает и обновляет секретный конфиг: локальная выдача администратору и внешний канал либо одноразовый защищённый портал; выбрать после анализа рисков.

## 5. Ограничения скорости и мониторинг

- **УТВЕРЖДЕНО.** Индивидуальные ограничения скорости на профили/устройства, задаваемые администратором; сохраняются после перезагрузок и не обходятся сменой страны выхода.
- **УТВЕРЖДЕНО.** Статистика отдельно по профилю, агрегированная по пользователю; при необходимости — RU/egress и ресурсы обеих VPS.
- **УТВЕРЖДЕНО.** Бот выполняет роль дашборда с графиками за разные интервалы, а также отправляет аварийные уведомления. CLI не зависит от бота и обеспечивает просмотр состояния.
- **УТВЕРЖДЕНО.** Система лёгкая: не развертываем Grafana, Prometheus, FRR, BIRD, ExaBGP и отдельную серверную БД без доказанной необходимости.
- **ПРОВЕРИТЬ.** Конкретная схема `tc` для отдельных направлений download/upload, способы надёжного учёта по AWG-пиру, точность измерений, стоимость хранения временных рядов.

## 6. Резервирование и эксплуатация

- **УТВЕРЖДЕНО.** Локальные резервные копии на RU плюс зашифрованная независимая копия вне RU. Восстановление возможно без Telegram.
- **УТВЕРЖДЕНО.** FR production AmneziaVPN сохраняется и после запуска нашей новой системы, если владелец не примет отдельного решения. Запрещено нарушать `amnezia-awg2`/Docker, сбрасывать firewall или менять маршруты без отдельного approval, baseline и восстановления.
- **УТВЕРЖДЕНО.** Для RU и зарубежного узла предусмотрены автостарт сервисов, диагностика и проверяемый откат; секреты не публикуются в чат, код и отчёты.

## 7. Границы решения

Не входят в MVP: BGP, внешние панели, обязательная учётная запись Telegram, клиентский IPv6, биллинг, сложная HA-схема, миграция или демонтаж существующего AmneziaVPN FR. Приёмка IPv6 должна проверять отсутствие нежелательного обхода VPN клиентским стеком.

## 8. Порядок работ

0. Нормативные документы и привилегированный read-only аудит RU/FR завершены; результаты и ограничения зафиксированы.
1. TASK 05: принят короткий изолированный smoke userspace AmneziaWG RU↔FR; подтверждены handshake, двусторонний UDP/TCP и cleanup. ICMP echo-request RU→FR блокируется общим FR nftables INPUT DROP; firewall не менялся и ICMP не требуется для подтверждения транспорта.
2. TASK 06: завершён изолированный постоянный host-level межсерверный AmneziaWG RU↔FR. Факты и ограничения записаны в `TASK_06_PERMANENT_AWG_TUNNEL.md`. 15-минутная нагрузка, reboot и клиентский egress остаются непроверенными.
3. Внедрить клиентский AmneziaWG на RU; затем PBR/NAT/fail-closed и DNS/списки.
4. Реализовать VPN Manager (SQLite, CLI, профили, лимиты, статистика), backup и операцию смены egress.
5. Добавить необязательный Telegram-адаптер и выполнить приёмку, включая ресурсы FR, IPv6-утечки, отказ egress и восстановление.

**Codex может выполнять read-only аудит с уже разрешённого SSH-доступа; изменения production только в пределах явно согласованного этапа и с проверяемым откатом.**
