# ACCEPTANCE — поэтапные критерии приёмки

Нельзя отмечать тест как пройденный без реального протокола выполнения, даты и подтверждающих результатов. Все проверки выполнять на разрешённой среде; негативные тесты — с планом восстановления.

## Этап 0 — проверка доступа исполнителя

- [ ] Исполнитель показал, какие конкретно инструменты доступа доступны **в текущей сессии**, а не предполагаются.
- [ ] Назван безопасный способ доступа и ограничения секретов; до проверки доступа никакой «аудит сервера» не объявлен выполненным.
- [ ] В случае отсутствия SSH исполнитель выдал read-only диагностический скрипт с инструкцией локального запуска; не просил пароли/ключи в чат.

## Этап 1 — аудит

- [x] Привилегированный read-only аудит RU/FR принят; адреса/маршруты, интерфейсы, firewall и защищённые FR Docker network metadata собраны без секретов. Production VPN data plane отдельно не подтверждался этим аудитом.
- [ ] Кандидат FR с 1 vCPU/961 МиБ прошёл требуемую проверку нагрузки перед production.


- [ ] RU: подтверждены Ubuntu, ядро, публичный интерфейс, маршруты, открытые порты, firewall, дисковые ресурсы.
- [ ] FR: задокументированы Docker containers, сети, существующая AmneziaVPN, действующие NAT и firewall-цепочки, порты и адресные конфликты.
- [ ] В отчёте отсутствуют секреты и приватные ключи.
- [ ] Проверен способ out-of-band восстановления SSH/доступ к консоли провайдера.
- [ ] Составлен план внедрения, отката и перечень **предлагаемых**, а не уже применённых, изменений.
- [x] FR `amnezia-awg2`/Docker не изменялись; отдельно отмечено, что чтение container state и проверка client data plane не были частью TASK 05 smoke.

## Этап 2 — входящий AmneziaWG RU

- [ ] Установлена совместимая серверная реализация на фактическом ядре; конкретная версия задокументирована.
- [ ] Тестовый профиль `Test_iPhone.conf` импортируется в согласованные клиенты; фиксируется реальное имя профиля после импорта.
- [ ] Клиент имеет доступ в интернет через публичный IPv4 RU и DNS RU.
- [ ] Клиентский IPv6 не выходит неуправляемым путём (проверены протокол и клиентский стек).
- [ ] Автозапуск и восстановление после reboot.
- [ ] Старый сервис на FR продолжает работать без изменений.

## Этап 2.5 — отдельный транспортный тест AWG-кандидата

- [x] Совместимость изолированного userspace AWG со стендом FR подтверждена коротким handshake и bidirectional UDP/TCP echo; тестовые порт/подсеть не пересекались с защищённой сетью/UDP 40905.
- [x] Владелец принял TASK 05 как успешный транспортный smoke. FR→RU ping 4/4; RU→FR ping 0/4 из-за nftables INPUT DROP всех ICMP на всех интерфейсах. Firewall не менялся. TCP/UDP echo по 1024 байта прошли в обе стороны, RX/TX выросли на обоих peers.
- [x] Cleanup тестовых интерфейсов, процессов и runtime state прошёл на RU и FR; default routes, SSH, firewall, sysctl и production Docker/VPN не менялись.
- [ ] 15-минутная устойчивость/нагрузка не проверена; это отдельная проверка перед клиентским egress.

## Этап 3 — выбранный межсерверный транспорт + PBR + fail-closed

- [ ] RU destination → внешний IPv4 RU; иностранный destination → внешний IPv4 FR. Результат проверен с клиента, а не только через `ip route`.
- [ ] `force_nl` перекрывает RU-геоклассификацию.
- [ ] Подмена/default-route host RU не произошла; SSH остаётся доступным.
- [ ] При остановке межсерверного туннеля RU→FR все FR-назначения блокируются, **ни один тестовый пакет не ушёл с RU IP**; RU-сайты доступны.
- [ ] При недоступном egress FR, но живом handshake, обнаружен отказ и нет аварийного переключения в RU.
- [ ] Проверены DNS, UDP, длинные TCP-сессии, MTU/MSS; нет незапланированного доступа к подсетям управления.
- [ ] В период миграции FR Docker AmneziaVPN проверена до/после вмешательства: её подключение, трафик и доступность сохранились.
- [ ] Обновление неверным списком не заменяет старую рабочую версию.

## Этап 3.1 — смена FR IP и замена VPS

- [ ] На RU файл межсерверного WG ссылается на постоянный hostname; локальное `getent ahostsv4` возвращает IPv4 из управляемой записи `/etc/hosts`.
- [ ] Смена записи `/etc/hosts` **без** переустановки активного WG не считается успешным переключением; проверены фактический активный endpoint, handshake, egress с IP зарубежного узла и отказоустойчивость.
- [ ] Команда менеджера смены IP (CLI и администраторский интерфейс, если он уже готов) не требует изменений `Ivan_iPhone.conf`/прочих клиентских конфигов и не перезапускает клиентский AmneziaWG.
- [ ] При недоступном новом IPv4 нет утечки зарубежный трафика с RU IP; фиксируется авария и выполнен проверенный rollback либо остаётся fail-closed.
- [ ] При полной замене VPS FR воспроизведены WG, ключи/согласованная ротация, обратный маршрут, NAT, firewall, проверен реальный FR egress и восстановлен приём зашифрованных бэкапов.
- [ ] Смена FR не перезаписывает несвязанные записи `/etc/hosts` на RU; операция защищена RBAC/аудитом и выдерживает повторный вызов.

## Этап 4 — менеджер и CLI

- [ ] `Ivan` создаётся именно как `Ivan`; повтор `ivan` и `IVAN` отклоняется с ясным сообщением.
- [ ] Для `Ivan` созданы `Ivan_iPhone`, `Ivan_MacBook` с разными ключами и IP, профили независимы.
- [ ] Администратор может создать пользователя без телефона, email и Telegram.

- [ ] Назначенные Admin лимиты скорости применяются в обоих направлениях и для обоих путей RU/egress; после перезагрузки сохраняются.
- [ ] Тестовые имена файлов: `Ivan_iPhone.conf`, `Ivan_MacBook.conf`; проверен реальный импорт.
- [ ] Нет рассогласования между SQLite, активными AWG-пирами и конфигурацией автозапуска при имитированном сбое одной операции.

## Этап 5 — Telegram-адаптер + мониторинг

- [ ] Неизвестный Telegram-отправитель не видит меню, метрики, имена и команды.
- [ ] Одноразовое приглашение используется не более одного раза; просроченное и отозванное отклоняются.
- [ ] Заявка не создаёт VPN-пир до решения Admin; одобрение/отклонение фиксируется.
- [ ] Только Owner может назначить нового Admin; только Admin/Owner меняет лимиты.
- [ ] Admin может вручную создать профиль для пользователя без Telegram.
- [ ] Пользователь с Telegram видит только собственные разрешённые профили/графики.
- [ ] Графики доступных периодов строятся по реальным данным, отдельно по профилю и суммарно по пользователю.
- [ ] Накопленные значения не становятся отрицательными при перезагрузке интерфейса и сбросе счётчиков.
- [ ] Бот остановлен на 10 минут: VPN, tc, PBR и CLI продолжают работать; затем бот стартует без повреждения данных.
- [ ] Проверена доставка и дедупликация аварийных сообщений, включая восстановление.

## Этап 6 — резервные копии и финальный ввод

- [ ] Расшифрование и восстановление на тестовом окружении проверено фактически (включая SQLite, ключи, профили и лимиты).
- [ ] Разрешённые права на каталоги и отсутствие секретов в логе, архиве проекта, коммитах и чатах подтверждены.
- [ ] Проведены тесты нагрузки, приближённой к 10–50 активным профилям; измерены CPU, RAM, пропускная способность, RTT и потери.
- [ ] Изданы runbook и инструкции аварийного восстановления RU и FR без Telegram.
- [ ] Перед эксплуатацией владелец проекта принимает отчёт по тестам и остаточным рискам.

- [ ] Production AmneziaVPN `amnezia-awg2`/UDP 40905 работает после каждой операции, затрагивающей FR networking; есть результаты реальных клиентских тестов до/после.
- [ ] Никаких задач планового удаления старого Docker/VPN в автоматизации или конфигурациях.
- [ ] Установлено, что при переключении зарубежного egress client RU AWG профили сохраняются, FR production VPN продолжает работать, а fail-closed не допускает утечек.
- [ ] Согласованы план и проверка отзыва обоих SSH-ключей Codex, с завершением уже открытых сессий.

## Протокол испытания

Для каждого теста: ID, дата, окружение/версии, предусловия, команда/метод, ожидаемое поведение, фактический результат, PASS/FAIL/BLOCKED, свидетельства без секретов, исправления, лицо, согласовавшее итог.
