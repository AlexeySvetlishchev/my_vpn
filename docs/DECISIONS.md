# DECISIONS — журнал архитектурных решений

Актуализировано 2026-11-07; старые D-01/D-02/D-03/D-04/D-17/D-19–D-22 пересмотрены по текущим решениям владельца. История ниже сохранена. Эти решения нельзя менять ссылкой на «best practices» без отдельного согласования владельца.

| ID | Статус | Решение |
|---|---|---|
| D-01 | SUPERSEDED | Две VPS: РФ и NL, Ubuntu 24.04 LTS, по 2 vCPU/4 ГБ RAM; диапазон 10–50 клиентов |
| D-02 | SUPERSEDED | РФ VPS чистая. NL: AmneziaVPN в Docker сохраняем **только на период внедрения**; после приёмки production старая инсталляция полностью выводится из эксплуатации и удаляется отдельным согласованным этапом |
| D-03 | SUPERSEDED | Клиентский вход — AmneziaWG; межсерверный транспорт — WireGuard |
| D-04 | SUPERSEDED | RU IP напрямую, остальные публичные IPv4 через NL; ручные исключения через NL |
| D-05 | SUPERSEDED | Fail-closed для NL, не делать fallback через RU |
| D-06 | УТВЕРЖДЕНО | Один DNS на RU, без клиентского IPv6 на первом этапе |
| D-07 | УТВЕРЖДЕНО | Лёгкая система, без обязательных тяжёлых сервисов BGP/Grafana и отдельной СУБД |
| D-08 | УТВЕРЖДЕНО | VPN Manager + обязательный CLI, Telegram — необязательный интерфейс, не источник истины |
| D-09 | УТВЕРЖДЕНО | Пользователь — имя администратора в неизменённом видимом виде; уникальность без учёта регистра |
| D-10 | УТВЕРЖДЕНО | Пользователь владеет несколькими независимыми VPN-профилями/устройствами |
| D-11 | УТВЕРЖДЕНО | Имя профиля/файла: `User_Device`, **подчёркивание**: `Ivan_iPhone.conf` |
| D-12 | УТВЕРЖДЕНО | Нет обязательных телефона/email/Telegram ID у VPN-пользователей |
| D-13 | УТВЕРЖДЕНО | Одноразовое приглашение → заявка → одобрение Admin для Telegram-самообслуживания |
| D-14 | УТВЕРЖДЕНО | Admin может создать VPN-пользователя и профиль вручную, в том числе без Telegram |
| D-15 | УТВЕРЖДЕНО | Лимиты скорости задаёт только Admin/Owner, персонально для профилей |
| D-16 | УТВЕРЖДЕНО | Telegram-дэшборд: графики по профилям/пользователям, серверная статистика, алерты |
| D-17 | SUPERSEDED | Локальные резервные копии плюс зашифрованная копия на NL |
| D-18 | УТВЕРЖДЕНО | Утверждённый проект нельзя перепроектировать исполнителю без change request |
| D-19 | SUPERSEDED | NL — сменяемый egress, смена публичного IPv4 и замена VPS без правки клиентских AWG-конфигураций |
| D-20 | SUPERSEDED | Межсерверный WG endpoint на RU задаётся hostname (пример `nl-egress.internal`), который разрешается через управляемую запись `/etc/hosts` на RU |
| D-21 | SUPERSEDED | При смене IP менеджер обновляет `/etc/hosts`, активный WG endpoint, проверяет egress, обеспечивает fail-closed и журнал изменений; `vpnctl nl set-ip` — запланированная CLI-команда |

## Регламент change request

Предложение изменения оформляется отдельной записью: затронутые D/H/Q, текущая схема, предлагаемое изменение, зачем, альтернатива без изменения, риски безопасности/доступности, план миграции и отката, проверки и явное решение владельца (`APPROVED`/`REJECTED`). Без явного решения владельца запрещено вводить новую production-архитектуру; актуальной является редакция 2026-11-07, а не прежний RU→NL baseline.
