# VPN RU → NL — проектный комплект (baseline v1.1)

Дата фиксации: 2026-11-03. Версия 1.1: смена NL endpoint и жизненный цикл старого Docker. Статус: **проектный baseline для утверждения владельцем**, не результаты настройки VPS.

## Назначение файлов

- `docs/SPEC.md` — обязательные функциональные и нефункциональные требования, границы и открытые вопросы.
- `docs/ARCHITECTURE.md` — целевая архитектура, потоки трафика, модель данных и план интеграции.
- `docs/SECURITY.md` — управление доступом, секреты, fail-closed, модель угроз.
- `docs/ACCEPTANCE.md` — приёмочные испытания и критерии готовности по этапам.
- `docs/DECISIONS.md` — журнал согласованных решений, технических гипотез и незакрытых вопросов.
- `docs/WORK_RULES.md` — обязательные ограничения для AI-исполнителей и людей.
- `docs/TASK_01_PREFLIGHT.md` — ограниченное стартовое задание: определить способ доступа, ничего не меняя.
- `docs/NL_ENDPOINT_RUNBOOK.md` — регламент смены публичного IPv4 и полной замены NL VPS.
- `docs/NL_MIGRATION.md` — две фазы NL, безопасное выведение старой AmneziaVPN/Docker из эксплуатации.

## Новое в v1.1

- **Действующая AmneziaVPN/Docker на NL — временная зависимость периода внедрения**. После приёмки новой системы она должна быть полностью выведена из эксплуатации и удалена отдельным одобренным этапом.
- **NL — заменяемая точка выхода**. На RU endpoint WireGuard указывается через стабильное внутреннее имя (пример `nl-egress.internal`), которое разрешается локальным `/etc/hosts`; смена IP должна применяться к активному WG peer с тестированием и возможностью отката.
- При смене или замене NL **клиентские AmneziaWG-профили не изменяются**. Сохраняется идентичность ключа межсерверного WG либо новая согласованная пара ключей вводится только на RU/NL.
- Процедура смены IP и удаления Docker не означает разрешение изменять серверы сейчас.

## Приоритет документов

1. Явное новое решение владельца проекта.
2. `SPEC.md` (утверждённые требования).
3. `SECURITY.md` (ограничения безопасности).
4. `DECISIONS.md` (зафиксированные решения).
5. `ARCHITECTURE.md` (проектный подход, **не** автоматическое разрешение на внедрение).
6. Задания исполнителям (`TASK_*.md`).

При противоречии остановить соответствующую работу, зафиксировать вопрос, не подменять требования своей интерпретацией.

## Статусы решений

- **УТВЕРЖДЕНО** — зафиксировано в переписке; не изменять без отдельного согласования.
- **ПРОВЕРИТЬ** — рабочая гипотеза; подтвердить аудитом/прототипом/документацией.
- **ОТКРЫТО** — нет решения владельца, нельзя выдавать предположение за обязательное требование.

Ни Work, ни иной исполнитель не должен повторно проектировать систему по общему техническому заданию. Изменения оформляются предложением (change request), а не тихой заменой архитектуры.
